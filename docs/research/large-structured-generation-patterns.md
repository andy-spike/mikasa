# Large structured generation patterns

Status: research input. This note surveys documented approaches for applications
that generate a large, structured artifact over many model calls. It does not
claim that any approach is better for Mikasa until it is measured against Course
coherence, generation time, and review findings.

## Consequences for the current delay

The current Course build already has the safer structure for dependent Lesson
prose: Course specification, ordered Lessons, a whole-Course review, then
targeted correction. ADR 0009 records why making Lesson writers parallel
created cross-Lesson defects. The external guidance agrees with the narrower
point that parallel work fits independent subtasks, not work with shared,
sequential context.

The main speed levers are therefore distinct:

1. Lower the duration of each model call through a faster model or provider,
   lower output or reasoning budgets where quality permits, and cached stable
   prompt prefixes where the provider supports it.
   The Course specification is another candidate: the mastery Depth asks one
   response to cover 45 Lessons. A bounded Module-level split may avoid
   repeating a large response after a timeout, but adds calls and a merge step.
2. Reduce input growth without losing continuity. A continuity ledger is a
   candidate complement to prior prose, but it needs an A/B Course evaluation
   before replacing any sibling prose.
3. Move only genuinely independent stages into bounded parallel work. This
   shortens wall-clock time without making dependent Lesson writing concurrent.
4. Keep the build durable and asynchronous so a long valid call is not cut off
   by the HTTP request lifetime. This improves completion reliability and the
   Learner experience, rather than token generation throughput.

## What this research does not establish

None of the cited sources measures a Course like Mikasa's or proves that a
continuity ledger, parallel review, lower reasoning effort, or a longer timeout
will preserve Course quality. The appropriate comparison is a small set of
identical Topics and Goals, recording stage duration, input/output and
reasoning tokens, validation failures, review findings, correction rounds, and
the final Course result.
